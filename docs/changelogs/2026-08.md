# Changelog — 2026-08

## 2026-08-03 — Dynamic State landed (spec 03, peer-review hardened)

- **The state turn is live.** After every reply (live turn, manual edit, or
  re-spin), one small second call distils the finished exchange into the turn
  summary + Sal's bounded inner state (`lib/dynamic-state.ts` pure half,
  `lib/state-turn.ts` call→commit half). The `<turn-summary>` contract left
  the main prompt entirely — Sal's reply is prose only; `parseTurnResponse`
  survives as a scrubber for legacy rows. The state feeds the next prompt as a
  private YOUR INNER STATE block (labeled lines, never JSON, privacy fence)
  rendered after the local buffer. Base loop is now 2 API calls/turn (worst 4
  with recall) — raised and accepted 2026-08-02; recurrence bounded by schema
  caps, per-turn regeneration, and user curation.
- **The rail's Dynamic State card** replaces the Turn Summary card: state
  fields + [ Edit ] (DynamicStateModal writes the latest persisted turn) +
  the summary lists + a "reflection · X in · Y out" token footer. It renders
  whenever the editor is usable — a failed state call keeps the control
  surface on screen — and shows the carried-forward D13 state (dimmed) when
  the latest turn has none. In-flight: "reflecting…", chat-scoped via the
  shared `hooks/useStateCalls.ts` registry (both producers report in).
- **Race hardening (post-review):** the state write is now a conditional,
  inspector-only PATCH — `{ inspectorJson, expectedContent }` →
  `db-turn-edits.ts updateTurnInspector`, one atomic
  `UPDATE … AND content = ?`, 409 on mismatch — so a state result can never
  land on (or revert) a reply edited while the call was in flight. This is the
  one sanctioned amendment to the spec's server-untouched line. In front of it
  sits a client write-epoch guard (same discipline, catches the same-content
  hand-edit case); `db.ts` crossed its ratchet budget in the process and the
  turn-rewrite helpers split into `db-turn-edits.ts`.
- **Injection fencing:** the state call's transcript moved out of the system
  prompt into the fenced user half; every parsed state/summary string is
  whitespace-collapsed so no field can forge prompt structure when it re-enters
  the next system prompt.
- **Honest accounting:** a billed-but-unparseable state response still records
  its tokens (null halves, usage kept); re-spins reset `apiCalls`/`recalls`
  (a recall-free re-spin no longer reads "paused to remember") and repeated
  manual edits no longer inflate the count; the inspector speaks in reply
  calls (state call excluded from the savings tile, D12); PhaseBar reads
  "2 API calls/turn"; README's worst case corrected to 4 total.
- The spec leaves the repo (specs are working documents, not committed
  artifacts — developer convention 2026-08-03): `docs/03_dynamic-state-spec.yaml`
  deleted from tracking; the final text (incl. its `amendments_2026_08_03`
  block) survives locally in the gitignored `docs/ignored/`. **Outstanding:**
  the LOCAL-path RP sanity pass (small-model behavior with the always-on
  inner-state block — the v1.3.0 lesson class) still needs a live local-model
  session.
- Verified: 454 tests across 26 files (57 new since the spec landed), all 3
  tsconfigs, lint, eval ledger unchanged (recall@3 1.000 / MRR 0.969).

## 2026-08-02 — Dynamic State spec (proposed, not yet implemented)

- `docs/03_dynamic-state-spec.yaml`: after each reply, one small second model
  call (the "state turn") produces BOTH the turn summary — moving the
  `<turn-summary>` contract out of the main prompt, freeing local-model RP
  replies from format burden — and a bounded persona internal-state JSON
  ("Dynamic State") that persists per assistant turn (inspector_json, the
  summary pattern), feeds the next prompt as a private-state block, and is
  user-editable from the inspector rail (the Dynamic State card takes the Turn
  Summary card's slot). Call-count raise accepted (base 2/turn, worst 4 with
  recall); the previous-state recurrence accepted deliberately with user
  curation as the drift control. Provider-agnostic: plain call, no tools.
