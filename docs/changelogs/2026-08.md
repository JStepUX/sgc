# Changelog — 2026-08

## 2026-08-30 — Citation cards open: RetrievalDetailModal + stem-aware highlights

- **The rail's grep and knowledge cards are now clickable receipts.** Each
  opens `RetrievalDetailModal` (portaled to body, Esc/backdrop/Tab-trapped)
  showing the FULL text that card served to the prompt — the complete user +
  assistant halves of a retrieved turn, or a brain fragment's whole chunk —
  with the terms that tipped the cosine score highlighted inline. The rail
  keeps its one-line previews; disclosure is progressive, per the modal-heavy
  house idiom (inline accordion considered in a stale 2026-05 spec and
  rejected: three expanded hits is ~2,500 tokens of prose in a 300px column;
  that spec is deleted, not refreshed — the work landed from session context).
- **The projection stops discarding what it already held.** `GrepDetail` now
  persists the served `userContent`/`assistContent`, `matchedTerms`, the
  `conceptScore × timeScore` anatomy, and `createdAt`/`timeless`;
  `KnowledgeDetail` persists the full fragment `text`. All optional — legacy
  `inspector_json` rows parse untouched and the modal degrades to the 80-char
  preview plus a "full text wasn't recorded" note. Snapshot-over-log-lookup is
  deliberate (argued out 2026-08-30): the citation key is a corpus pair index
  that gating/tangent-wipe/edits can drift out from under, and brain fragments
  have no log to consult once a pack unmounts — dumb data written at the
  moment of truth beats a render-time join.
- **Engine report widened, Sal's prompt byte-identical:** `MATCHED_TERMS_CAP`
  3 → 8 (tfidf.ts) so the highlight set has coverage; `formatGrepFragment`
  slices the top 3 (`PROMPT_PROVENANCE_TERMS`, prompt.ts) — terms rank by
  contribution, so the `via "…"` prefix is unchanged. Tests pin both caps.
- **`lib/highlight.tsx`** — matched terms are Porter STEMS, so highlighting
  runs each display word through the same `tokenize()` that built the corpus
  (the 2026-05 spec's plain string-compare would have highlighted nothing).
  Highlight ⇒ contributed; not the converse (terms past the cap stay unmarked).
  Brain fragments get no highlights — deliberate deferral: their vectors match
  on text+summary+topics+aliases, so a tipping term can be invisible in the
  fragment text; honest highlighting there needs its own design.
- **Peer-review hardening (Codex, 5 findings: 3 confirmed, 1 relabeled, 1 was
  the deferral above):** an open modal now closes when the next turn's
  diagnostics replace the rail (TurnInspector stays mounted across turns —
  `useState` does NOT reset on re-render, and the original comment claiming it
  did was itself the bug); the dialog traps Tab per its `aria-modal` promise;
  the meta row is relabeled `matched "…"` and documented as deliberately
  richer than Sal's 3-term `via` prefix (viewing-time-relative date included —
  serve-time isn't persisted).
- Verified: 479 tests across 28 files (8-test highlight suite + cap/slice
  coverage new), all 3 tsconfigs, lint, eval ledger unchanged; developer
  visual pass in the Electron dev shell (modal open/close, legacy degrade
  note on pre-change turns).

## 2026-08-11 — Ephemeral tangents landed (spec 04, peer-review hardened)

- **The tangent axis is live.** The ⑂ button beside the composer stamps a
  boundary (`chats.tangent_start` = MAX(ordinal) at entry, one nullable column,
  additive migration) and the conversation just continues — same loop, same
  retrieval, same state turn; Sal is never told (D5). A strip above the
  composer resolves it: **Make canon** clears the boundary (turns were stored
  canon-shaped all along — canonization is a no-op on the turns table);
  **Wipe** (inline confirm) deletes every non-timeless turn past the boundary
  in one transaction. Because Dynamic State and turn summaries live as per-turn
  `inspector_json` snapshots, deleting the rows IS the state rollback — no
  shadow store, no replay. Wipe is `useTurnUndo` generalized from "latest pair"
  to "everything past the boundary": persist-first, full server resync,
  degraded local surgery on resync failure. Crash-safe: reload mid-tangent
  re-adopts the open boundary (tint, divider, strip, count).
- **Server:** `db-tangent.ts` (begin/resolve lifecycle; the `timeless = 0`
  DELETE guard is defense-in-depth — prepends can't land past the boundary,
  but an API caller must still be unable to wipe a curated memory) + two routes
  mirroring the latest-turn undo's error shape. Neither lifecycle move bumps
  `updated_at`. 12 behavioral tests, including forcing a timeless row past the
  boundary with raw SQL to prove the mutation-level guard holds without the UI.
- **No curation freeze** (reverses the brainstorm position): every memory-editor
  mutation is boundary-safe by construction — gating flips flags on surviving
  rows, manual memories prepend BELOW the boundary (negative ordinals), manual
  deletes touch only timeless rows the wipe spares. Tested, not trusted (the
  D2 ordinal-stability test). The only guard that survived review: undo/pencil
  disable while a tangent is open with zero tangent pairs, so they can't reach
  across the boundary into canon.
- **Peer-review hardening (Codex, 4 findings, all confirmed):** (1) tangent
  state is recomputed from ordinals at EVERY detail adoption — `canonEntries`
  is an entry-index-space count and undo's resync can fold manual prepends into
  the visible log, which previously drifted the guard far enough to let a
  second undo delete a canon pair; `tangentFrom` is now the exported single
  source of that law. (2) A wipe holds tangent state open (+ new `resolving`
  flag disabling composer/strip) until its resync settles — no window where a
  submit builds a prompt from already-deleted history. (3) `chatIdRef` guards
  every post-await state application in `useTangent` AND `useTurnUndo` (same
  latent race predated the feature) — nothing fetched for one chat applies
  after a switch to another. (4) A lifecycle 409 (another window moved the
  tangent) adopts the WHOLE server detail, never the boundary alone — a
  boundary-only adopt against stale messages would recreate finding 1.
- **Ratchet split:** the tangent state pushed `useChatSession` to the 500-line
  ceiling; the memory-edit resync trio moved to `hooks/useMemoryEditSync.ts`
  (spec 04's designated split — 467/500 after).
- Chat-scoped documents (constitutional, persona, brains) are per-chat, not
  per-turn — edits during a tangent survive a wipe (D9, accepted; README says
  so where the feature is described).
- Verified: 470 tests across 27 files (16 new), all 3 tsconfigs, lint, eval
  ledger unchanged (recall@3 1.000 / MRR 0.969); live Playwright pass on the
  full lifecycle (begin → reload-restore → wipe → canon), the manual-memory
  fold scenario, and the stale-window 409 adoption.

Released as **v1.5.0** (Windows NSIS installer).

## 2026-08-07 — Spontaneity recalibrated: light-touch register + threshold raise

First dogfooding verdict on the spontaneity engine: firing too often, and far
too loud — characters actively derailed by ambient noises and stray cats, and
`environmental_shift` rendering every weather event as a house-shaking
thunderstorm. Wording was made the primary lever, frequency the secondary one
(developer's call: "subtle first, then slightly less often").

- **The whole deck reworded into a light-touch register** (`flexDeck.ts`; ids,
  names, and weights unchanged, so no-repeat tracking and snapshotted old turns
  are untouched). The maximal verbs went — "overtakes this moment", "focus
  fractures", "the world has its own opinion" — replaced by wording that asks
  for a background note: passing mentions, half-beats, one precisely placed
  clause. `environmental_shift` now explicitly keeps weather at a distance
  ("heard through a window, never shaking the house"); `passive_refusal`
  softened from "Do not answer. Leave." to a gentle sidestep. `tonal_undertow`
  was already in this register and is unchanged. A REGISTER note in the file
  header makes the calibration binding for future deck edits.
- **A global "light touch" clause in the `⟐` prompt block** (`prompt.ts`):
  "let it color your reply, not commandeer it — a background note, never the
  event of the turn." Covers every operator at the single injection point.
- **`DEFAULT_SLACK_THRESHOLD` 0.3 → 0.35** (`slackDetector.ts`) — the "slightly
  less often" half. The 2026-07-03 stemming replay had already shown 0.3 sat
  below the dev-chat mean (0.338); 0.35 moves the line just above it. The
  module README's calibration caveat is now a calibration history.

## 2026-08-03 — Dynamic State landed (spec 03, peer-review hardened)

- **The state turn is live.** After every reply (live turn, manual edit, or
  re-spin), one small second call distils the finished exchange into the turn
  summary + Sal's bounded inner state (`lib/dynamic-state.ts` pure half,
  `lib/state-turn.ts` call→commit half). The `<turn-summary>` contract left
  the main prompt entirely — Sal's reply is prose only; `parseTurnResponse`
  survives as a scrubber for legacy rows. The state feeds the next prompt as a
  private YOUR INNER STATE block (labeled lines, never JSON, privacy fence)
  rendered after the local buffer. Base loop is now 2 API calls/turn (worst 4
  with recall) — raised and accepted 2026-08-02; recurrence bounded by schema
  caps, per-turn regeneration, and user curation.
- **The rail's Dynamic State card** replaces the Turn Summary card: state
  fields + [ Edit ] (DynamicStateModal writes the latest persisted turn) +
  the summary lists + a "reflection · X in · Y out" token footer. It renders
  whenever the editor is usable — a failed state call keeps the control
  surface on screen — and shows the carried-forward D13 state (dimmed) when
  the latest turn has none. In-flight: "reflecting…", chat-scoped via the
  shared `hooks/useStateCalls.ts` registry (both producers report in).
- **Race hardening (post-review):** the state write is now a conditional,
  inspector-only PATCH — `{ inspectorJson, expectedContent }` →
  `db-turn-edits.ts updateTurnInspector`, one atomic
  `UPDATE … AND content = ?`, 409 on mismatch — so a state result can never
  land on (or revert) a reply edited while the call was in flight. This is the
  one sanctioned amendment to the spec's server-untouched line. In front of it
  sits a client write-epoch guard (same discipline, catches the same-content
  hand-edit case); `db.ts` crossed its ratchet budget in the process and the
  turn-rewrite helpers split into `db-turn-edits.ts`.
- **Injection fencing:** the state call's transcript moved out of the system
  prompt into the fenced user half; every parsed state/summary string is
  whitespace-collapsed so no field can forge prompt structure when it re-enters
  the next system prompt.
- **Honest accounting:** a billed-but-unparseable state response still records
  its tokens (null halves, usage kept); re-spins reset `apiCalls`/`recalls`
  (a recall-free re-spin no longer reads "paused to remember") and repeated
  manual edits no longer inflate the count; the inspector speaks in reply
  calls (state call excluded from the savings tile, D12); PhaseBar reads
  "2 API calls/turn"; README's worst case corrected to 4 total.
- The spec leaves the repo (specs are working documents, not committed
  artifacts — developer convention 2026-08-03): `docs/03_dynamic-state-spec.yaml`
  deleted from tracking; the final text (incl. its `amendments_2026_08_03`
  block) survives locally in the gitignored `docs/ignored/`. **Outstanding:**
  the LOCAL-path RP sanity pass (small-model behavior with the always-on
  inner-state block — the v1.3.0 lesson class) still needs a live local-model
  session.
- Verified: 454 tests across 26 files (57 new since the spec landed), all 3
  tsconfigs, lint, eval ledger unchanged (recall@3 1.000 / MRR 0.969).
