## 2026-09-03 — Reply pacing: a drawn paragraph ceiling, enforced at the break

- **Why.** 512-flat was wrong twice over: a small local model treats any cap
  as a target and fills it every turn (six paragraphs for a two-line beat),
  and a thinking model needs the cap roomy anyway because the `<think>` block
  comes out of the same budget. "How much progress to make this turn" is a
  judgement call the local models can't hold from a sentence of guidance,
  and sizing the reply off the person's input would read as mirroring
  (ruled out). So: random, bounded, enforced — and shown only after the fact.
- **The draw (`src/client/lib/pacing.ts`).** Each reply gets a paragraph
  ceiling from a weighted deck (1–5, weighted to 2–3, never the same twice
  running), blind to the input. Same shape as the spontaneity engine:
  injectable RNG, no module state — the no-repeat rule reads the previous
  ceiling off `latestTurn` (restored on load/undo/tangent like everything
  else there), so no new ref threads through the hooks. Snapshotted onto
  `TurnData` (`pacingCeiling` / `pacingOutcome` / `pacingTrimmed`, via a
  `PacingInspector` the type `extends`); a re-spin always REPLAYS the ceiling
  (it's the turn's bound, not a perturbation to undo); a hand edit keeps the
  ceiling and clears the outcome.
- **The prompt.** With a ceiling the tail's pacing line names the number
  ("within a ceiling of N paragraphs this turn: fewer is fine when the beat is
  done…"); without one, this morning's judgement-only wording. The shared
  opening stays a pinned tail marker.
- **The cut (`src/server/paragraph-cap.ts` + `turn-route.ts`).** Reply calls
  carry `maxParagraphs`; the route feeds every visible delta through a pure
  blank-line counter and, at the Nth break, aborts upstream and closes with
  stopReason `max_paragraphs`. No sentence detection anywhere — a break is
  `\n[ \t]*\n`, nothing else (ruled: sentence heuristics against RP prose are
  scar tissue). A trailing newline run is held back across fragments so a
  straddling break still counts; empty paragraphs never count; an
  under-ceiling reply is byte-identical to no cap. The state turn never sends
  the field, so its JSON is untouched. The regex is duplicated client/server
  (the server can't import client code) and both copies are pinned against
  the same fixtures.
- **The fallback (client, `api.ts`).** A paced call that hit `max_tokens`
  first is trimmed back to its last complete paragraph — client-side, since
  the half paragraph is already on the wire and deltas can't retract. No
  break at all → nothing trimmed, truncation left visible, inspector says so:
  one paragraph that outran the whole budget is a broken generation, not a
  pacing problem. Unpaced calls (the state turn) are never trimmed.
- **Inspector.** A `¶ ceiling N paragraphs · <outcome>` card on paced turns
  (after the fact only — the draw is meant to be unpredictable at the
  composer).
- **To verify on the machine, not in tests:** KoboldCPP runs one generation
  at a time. If it keeps generating after the route drops the connection at
  a cut, the state turn queues behind the phantom tail and summaries land
  late after every cut. Recent builds are believed to stop on disconnect; if
  they don't, the fix is one extra request to Kobold's abort endpoint on cut.
- Tests: 42 new — deck weights / no-repeat / dead-card sweep, trim cases
  (incl. dialogue + markdown punctuation left alone), the server counter
  (straddling breaks, held whitespace, empty paragraphs, char-at-a-time
  equivalence), the route end-to-end over real HTTP with a fake provider
  (cut + abort + done frame, under-ceiling passthrough, no-cap path, 400s),
  `runTurn` trim semantics, recall-loop forwarding, prompt line variants.
- **Codex review (Sol), three findings, all confirmed against the code and
  fixed:** (1) the hard-cap trim treated a break at offset 0 as a paragraph
  end and could persist an EMPTY reply for text opening with blank lines —
  now a break only counts with real text before it, same rule as the server
  counter; (2) a cut turn reported usage as a measured 0, which the
  Context-Savings tile read as 100% saved — the route now sends null, the
  client estimates over what actually went on the wire and flags it
  (`usageEstimated`; the tile labels Sent "(est.)"), and a local server that
  omits usage (the pre-existing silent-0 case) gets the same treatment; (3)
  the ceiling was per REQUEST, so a recall turn could spend it once per
  round — the recall loop now subtracts paragraphs already committed from
  earlier rounds (floor 1). Sol could not run Vitest in its read-only
  sandbox; typecheck passed there, the full suite passed here.
- **Re-spin can change the ceiling (dogfooding follow-up).** The edit-reply
  modal now carries a paragraph-ceiling picker (1–5, or none) beside the
  operator replay toggle, defaulting to the turn's own ceiling — a faithful
  replay unless changed. The saved turn records the ceiling that actually
  ran (`RespinResult.ceiling` → `pacingCeiling`), so the inspector card and
  the next draw's no-repeat rule see the truth. Motivation: the usual reason
  to re-spin a cut reply is that the draw was too small for the beat.
- **Seams logged, not fixed:** `docs/06_turn-pipeline-seams-spec.yaml` (status
  proposed) records the two seams this landing exposed — one per-turn field
  touches five shapes, and the two per-turn draws are hand-wired through
  runner, editor, assembler and prompt — with the trigger conditions (next
  per-turn field, third draw, Stop/Continue, a 15th buildPrompt param) and the
  ordered refactor. Nothing scheduled.

## 2026-09-03 — LOCAL path: thinking models (Qwen3 & co.) and the output cap

- **`<think>` blocks are separated at the provider boundary.** A reasoning
  model on the LOCAL provider used to stream its whole chain of thought into
  the thread: persisted as the reply, re-entering the local buffer and
  Grepory, and sitting in front of the state turn's JSON. `separateThinking`
  (`src/server/openai-provider.ts`) now splits raw content into visible reply
  + reasoning, once, for both producers (live turn and state turn). It is a
  pure, prefix-stable function of the content-so-far — a trailing partial tag
  is held back until the next fragment disambiguates it — so the append-only
  delta contract to the client holds. `delta.reasoning_content` /
  `delta.reasoning` (servers that split thinking for you) route to reasoning
  too. Reasoning is dropped, not surfaced (ruled: not interested in seeing it).
  One shape is deliberately unhandled: a template that pre-fills `<think>` so
  only a bare `</think>` arrives — undecidable mid-stream; the stray tag is
  dropped and the fix is the server-side split (llama.cpp `--reasoning-format`).
- **Thinking-only replies are an error, not a blank turn.** If the visible
  reply is empty but reasoning isn't, `streamTurn` throws an actionable
  message naming `LLM_MAX_TOKENS` (when `finish_reason` was `length`) instead
  of letting the buffers and state turn run on nothing. `finish_reason` is now
  mapped to the client vocabulary (`stop`→`end_turn`, `length`→`max_tokens`);
  it was hardcoded to `end_turn`, so a truncated reply looked finished.
- **`LLM_MAX_TOKENS` default 512 → 4096, and re-framed as a ceiling.** The
  thinking comes out of the same budget before the reply starts, so 512 never
  reached a reply on Qwen3. Copy in `.env.example`, `index.ts`, the desktop
  provider modal and README now says ceiling-not-target.
- **Reply length is steered by the prompt, not the cap.** Small local models
  treated 512 as a target and filled it every turn — six paragraphs for a
  two-line beat. A persona-neutral pacing line joined the architectural tail
  of `lib/prompt.ts` ("Size your reply to the moment…"), pinned as a tail
  marker in `prompt.test.ts`. This is every-turn prompt copy and therefore a
  behavioural change to BOTH providers (AGENTS.md rule) — it wants a LOCAL
  sanity pass on Qwen and an eye on Opus; gate it to LOCAL if Opus tightens.
- Tests: 20 new in `providers.test.ts` (separation contract incl. a
  character-by-character prefix-stability walk, split tags, held-back `<`,
  reasoning_content routing, finish_reason mapping, and the provider guard via
  a stubbed `fetch`).

## 2026-09-01 — Fix: electron-builder implicit publish crashed the first DMG run

- **`--publish never` pinned in both dist wrappers.** The v1.6.1 tag's CI run
  built the DMG successfully, then died in electron-builder's *implicit*
  GitHub publish (auto-enabled when a git tag is detected; no `GH_TOKEN` in
  the build step — deliberately, since the workflow's upload step is the only
  publisher). The `sgc_v1.6.1` tag was re-pointed at this fix to re-fire the
  workflow; the release association is by tag name and survives.

## 2026-09-01 — Release runbook (`docs/releasing.md`)

- **The release sequence is now documented, not tribal.** Bump → changelog →
  verify → `dist:win` → gate → tag → `gh release create` (human-authored
  notes) → CI DMG attach, with the naming facts (`sgc_vX.Y.Z` tags, artifact
  names bound to `package.json` version), the mac-leg recovery paths, the
  icns regeneration rule, and the deliberate v1.3–v1.5 publication gap.

  session transcript that shipped v1.6.0.

  `sgc_v*` tag, the exact blind spot that let 1.3.0–1.5.0 ship untagged and
  unpublished for two months. Advisory, not blocking: the mismatch is legal
  in the minutes between a release commit and its tag (runbook steps 5–6).
