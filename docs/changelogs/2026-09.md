# Changelog — 2026-09

## 2026-09-01 — Fix: electron-builder implicit publish crashed the first DMG run

- **`--publish never` pinned in both dist wrappers.** The v1.6.1 tag's CI run
  built the DMG successfully, then died in electron-builder's *implicit*
  GitHub publish (auto-enabled when a git tag is detected; no `GH_TOKEN` in
  the build step — deliberately, since the workflow's upload step is the only
  publisher). The `sgc_v1.6.1` tag was re-pointed at this fix to re-fire the
  workflow; the release association is by tag name and survives.

## 2026-09-01 — Release runbook (`docs/releasing.md`)

- **The release sequence is now documented, not tribal.** Bump → changelog →
  verify → `dist:win` → gate → tag → `gh release create` (human-authored
  notes) → CI DMG attach, with the naming facts (`sgc_vX.Y.Z` tags, artifact
  names bound to `package.json` version), the mac-leg recovery paths, the
  icns regeneration rule, and the deliberate v1.3–v1.5 publication gap.
  Pointed to from CLAUDE.md's Committing section and indexed in
  `docs/README.md`. Before this, the sequence lived only in the 2026-09-01
  session transcript that shipped v1.6.0.
- **Tripwire (Core Value #3):** `health-check.sh` gains a Release Drift
  section — warns when `package.json` disagrees with the latest reachable
  `sgc_v*` tag, the exact blind spot that let 1.3.0–1.5.0 ship untagged and
  unpublished for two months. Advisory, not blocking: the mismatch is legal
  in the minutes between a release commit and its tag (runbook steps 5–6).

## 2026-09-01 — macOS packaging: CI-built arm64 DMG (spec 05)

- **SGC packages for mac without touching `src/**`.** `package.json` gains a
  `"mac"` builder block (dmg, arm64-only, icns generated from the new
  `public/sal_logo_512.png`, `identity: null` — unsigned by ruling P2) and a
  `dist:mac` script wrapping the new `scripts/dist-mac.mjs`, a sibling of
  `dist-win.mjs` that keeps the force-rebuild + finally-restore + `.forge-meta`
  scrub (the marker trap is platform-general; the script must be safe on a
  physical mac even though CI's node_modules is ephemeral).
- **`.github/workflows/release-mac.yml` (the repo's first workflow):** a
  `sgc_v*` tag push builds the DMG on `macos-latest` (arm64) and uploads it to
  that tag's *existing* release — upload only, never create; the hand-authored
  release notes stay the source of the body. Build-only by ruling P4: the local
  gates already ran before the tag existed.
- **Honest posture, ruled 2026-09-01: the developer has no Mac.** The DMG ships
  unsigned *and* untested on real hardware; README's new Desktop (macOS)
  section says so and documents the Gatekeeper escape (right-click → Open /
  `xattr -cr`). The spec's mac-hardware verification checks are permanently
  open — a standing invitation for a mac-equipped contributor, not a gate.
  Consequence noted in the spec: unsigned forecloses mac auto-update
  (Squirrel.Mac requires a signed app) until signing is ever bought.
- Also: darwin no-op note in `electron/spellcheck.ts`'s header (mac uses the
  OS-native spellchecker; the empty-list guard already made that safe), README
  script table + repo-layout line updated, AGENTS.md's better-sqlite3 ABI-check
  instruction now names the darwin-arm64 asset (verified present for
  electron-v145 / v12.10.0 via the GitHub release assets).
- Released as **v1.6.1 — Mac Compatibility** (Windows NSIS installer + the
  first CI-built macOS DMG; the release runbook and release-drift tripwire
  ride along).
- **Peer-review hardening (Codex, 6 findings, all confirmed on interrogation;
  one overstated):** the upload step now *waits* for the hand-created release
  instead of racing it (never creates one); a tag ≠ `package.json` version
  mismatch fails the run before a wrong-versioned DMG can ship;
  `dist-mac.mjs` pins `--arch arm64` (electron-rebuild defaults to the HOST
  arch — an Intel mac would have packaged an x64 sqlite module into the arm64
  app); `workflow_dispatch` added as a build-only smoke; and the icns is
  **pre-generated** into `resources/icon.icns` with png2icons because
  electron-builder 26.15.2+ icns generation drops the non-retina 16/32
  entries (upstream #9940) — the generated file's entry table was inspected
  locally (`is32`/`il32` present). Three stale doc claims fixed: README
  install step, `main.ts` quit-on-close P3 note, `spellcheck.ts`'s
  "SGC ships Windows-only".
