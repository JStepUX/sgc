## 2026-07-24 — Spontaneity: Tonal Undertow replaces Emotional Non-Sequitur; re-spin drops the operator by default

**Deck swap.** The `emotional_nonsequitur` operator ("cheerful when gravity is
expected, or quiet when energy is expected") produced a creepy, mood-spoiling
cheerfulness in practice — inverted affect over a grave moment reads as
callous, and "do not explain it" forbade any repair. Replaced by
`tonal_undertow`: the surface register fits the moment while an unnamed
undercurrent colors word choice — subtext instead of inversion. Old turns keep
rendering their original marker/directive (snapshotted in `inspector_json`).
Also reconciled a doc/test contradiction found on the way in: the `Operator`
interface claimed `weight: 0` soft-removes an operator from the draw, but the
structural test requires positive weights — the doc now says what the test
enforces (deletion is the removal path).

**Re-spin × operators.** A re-spin previously replayed the turn's fired
operator byte-for-byte, which made re-spinning a perturbed turn reproduce the
perturbation you were trying to undo. Now:

- By default a re-spin runs **without** the fired operator; on save, the turn's
  fired fields and the ⟐ marker are cleared so the record matches the
  regenerated text (the slack similarity reading stays — it measures the prior
  log, not the injection). A toggle in the edit-reply modal (shown only when an
  operator fired) opts back into the verbatim replay. Neither path redraws.
- Clearing follows *provenance*, not verbatim-ness: a hand edit on top of a
  clean re-spin still descends from unperturbed text, so it clears too
  (review finding P1).
- Clearing also re-pulls the spontaneity no-repeat cursor from the DB with the
  same scan load/undo use, so the live session agrees with what a reload would
  compute (review finding P2).

## 2026-07-10 — Prompt-order fixes (the v1.3.0 plot-loss regression) + turn undo

**Prompt fixes.** Developer testing on the LOCAL provider found v1.3.0 notably
worse than v1.2.0 at holding a running narrative — losing details from one turn
ago, especially when a stale grepped memory contradicted the live exchange
("woke up" one turn ago losing to "they're asleep" from days back). Two causes,
both in `buildPrompt`, both fixed:

- **The absence marker is now gated on `recallEnabled`.** It shipped
  unconditional: every empty-grep turn told the model "(nothing from older
  history surfaced)" — which is most mid-plot turns, since the plot lives in
  the buffers. For Opus that's ignorable; for a small local model it reads as
  "you don't remember this" every turn and destabilizes thread-following. The
  marker's own rationale (D7: absence is *actionable* with recall) only holds
  where the recall tool exists, so it now renders only there — the LOCAL
  prompt's empty-grep branch is back to v1.2.0 shape. Regression test pins it.
- **History tiers now render chronologically** — RETRIEVED HISTORY (furthest
  back) → EARLIER CONTEXT (distilled) → RECENT CONTEXT (verbatim last
  exchange) — where the old order was exactly backwards, putting the stalest
  tier closest to the task instructions (the high-attention late-prompt
  position). Precedence is also now *stated*, on both ends: retrieved history
  is "background from further back, superseded by anything more recent below,"
  and recent context is "the present state — where anything older disagrees,
  THIS is what's true now." Ordering test pins grep < distilled < recent <
  YOUR TASK.

**Turn undo.** A hover-revealed ↺ beside the latest reply's pencil ("Undo this
turn"): deletes the user+assistant pair — always both halves; the cosine
engine and buffers assume strict alternation — and returns the user's text to
the composer, focused, for edit-and-resubmit ("Give me a good cat name that
isn't Mr. Wigglesworth"). Deterministic curation of the memory tier, no model
in the loop; undo repeatedly, back to an empty chat.

- **Server**: `deleteLatestTurnPair(chatId, expectedAssistantId)` in db.ts +
  `DELETE /api/chats/:id/latest-turn/:assistantTurnId`. The client names the
  assistant id it believes is latest; the server verifies before deleting —
  a stale client (a turn landed since / another window undid first) gets a
  409, never a wrong-pair delete. Timeless manual memories are unreachable
  (latest row must be a non-timeless assistant). 7 new db tests.
- **Client**: new `hooks/useTurnUndo.ts` (persist-first, then a full detail
  re-pull — the now-latest turn's inspector blob and the spontaneity no-repeat
  cursor live only in the DB, so a re-pull is the only honest restore; local
  filter fallback if the re-pull fails). Composer gains a `seed` prop
  (monotonic-nonce shape, mirroring `resetSignal`) for the returned draft.
  Corpus/buffer removal is automatic — both derive from chatLog. The undone
  turn's token-chart bar drops; the history rail snippet refreshes without
  reordering (updated_at not bumped — undo is curation, not activity).
- Verified: 382 tests / typecheck / lint / ratchet green; route smoke-tested
  over HTTP (409 stale, 200 latest, 400 garbage, survivors correct); full UI
  flow driven with Playwright on a scratch DB — controls reveal on hover on
  the latest reply only, undo returns the text to a focused composer, controls
  migrate to the new latest reply, undo-to-empty lands on the empty-state copy.
- Released as **v1.3.1** (Windows NSIS installer).

## 2026-07-06 — Deliberate recall: Sal queries its own history mid-turn (spec 01)

Sal gains a **`recall` tool**: mid-turn, it can pause and re-query the SAME
deterministic engine (`searchScored`) with a query it authors — ambient
retrieval unchanged, deliberate recall added on top. Client-orchestrated loop
(the corpus never leaves the browser, D1), Anthropic-only in v1 (D2), max 2
recall rounds so a turn is ≤ 3 API calls worst case (D3 — the consciously
amended guardrail, raised and approved 2026-06-09; CLAUDE.md Mission Brief now
names it). The invariant holds: the model proposes a QUERY, the math disposes —
ranking/threshold/ordering stay 100% `searchScored`, and nothing model-generated
persists past the turn (Sal stays ephemeral). All user/Sal-visible naming is
diegetic: the tool is `recall`, the status line is "Remembering…" — no
grep/TF-IDF jargon outside the inspector.

- **Two tool modes** (D4): `query` runs the identical params as ambient
  retrieval (a recall differs only in who authored the query); `around_turn`
  fetches turn N±1 deterministically — the bounded episode mechanic. A per-turn
  dedup set seeded from the ambient grep keeps recall widening context, never
  duplicating it (D5); buffer/summary-window neighbors come back as "that turn
  is already in your recent context" instead of silence.
- **Provenance + absence marker ride along** (D7): every retrieved fragment —
  ambient and recalled, one shared `formatGrepFragment` — now carries its top
  matched terms (`[Turn 6 · 4 min ago · via "sister"]`, computed inside
  `cosineSearch` where both TF-IDF vectors are in scope; additive, ranking
  byte-identical, eval ratchet re-measured green). And when older history
  exists but nothing cleared threshold, the prompt says so out loud instead of
  omitting the block — with recall enabled, that absence becomes actionable
  ("— if something feels missing, recall for it.").
- **New modules, pure and server-free**: `lib/recall.ts` (one tool call's
  retrieval; honest-empty strings, never throws — a malformed call must not
  abort the turn per D8) and `lib/recall-loop.ts` (round control, cross-round
  text concatenation per D6, token summing, status callbacks; `callTurn`
  injectable). 29 new tests across them + engine/prompt/api additions.
- **Transport**: `TurnRequestBody` widens back-compatibly to
  `messages: WireMessage[]` + `tools` passthrough — the server forwards blocks
  verbatim and still doesn't know what `recall` is. SSE gains a `tool_use`
  frame and `stopReason` on `done`. The anthropic provider streams text as
  before and reads tool_use blocks from `finalMessage()` (fully parsed by the
  SDK — no `input_json_delta` hand-assembly needed, as the spec predicted).
  LOCAL ignores tools entirely; wire-inspected: no `tools` key, no recall
  framing in the prompt, behavior identical to before.
- **The ratchet fired on both server files mid-build and was obeyed**:
  providers.ts (550 > 500) and index.ts (930 > 920) split into
  `openai-provider.ts`, `provider-types.ts`, `wire-types.ts`, and
  `turn-route.ts` (the whole `/api/turn` route, same pattern as
  brains-routes.ts). index.ts is down to 788 lines.
- **UI**: a quiet "Remembering…" line (muted-meta style, gentle pulse) under
  any already-streamed text while a recall round-trip runs; inspector gains a
  "Deliberate recall" trace line + per-event cards (round, query/around_turn,
  match count) via `TurnData.recalls`/`apiCalls`, and the Context Savings copy
  now reports the real call count ("2 API calls this turn — Sal paused to
  remember") instead of a hardcoded "1".
- **Two deliberate spec deviations, both toward honesty**: an all-deduped query
  result says "everything that matched is already in front of you" (the spec's
  "may not exist" string would be false there), and `RecallEvent.round` is the
  API round (a multi-tool round shares a number) with `apiCalls` added beside
  it.
- Verified: 374 tests / 3 tsconfigs / lint / architecture ratchet green, plus a
  live Opus smoke driven by Playwright — planted timeless fact + oblique probe
  (ambient miss → Sal recalled "Maren sister location city", the constitutional
  document supplying the name: the designed synergy), honest-empty on a
  never-discussed topic (no fabrication), `around_turn` neighbors with dedup
  holding, "Remembering…" render confirmed via MutationObserver, and a LOCAL
  turn wire-captured tool-free.
- Released as **v1.3.0** (Windows NSIS installer).
- Spec archived at `docs/ignored/01_deliberate-recall-spec.yaml`.

## 2026-07-05 — Constitutional memories: chip list retired for one freeform document (spec 00)

The Memory[] chip list (M1/M2/M3 cards + a single-line add input — the format
that sat empty since inception per the developer's own confession) is replaced

- **DB migration, not a shim** (D1): `chats` gains `constitutional TEXT NOT
  NULL DEFAULT ''`; a one-time migration concatenates any existing `memories`
  rows per chat (`created_at` order, newline-joined) into the new column, then

  never capped, and an over-cap aggregate would be un-saveable and

  storage can't disagree.
- **Create-failure recovery** (review finding): `startNewChat` cleared the
  session before `apiCreateChat` resolved and its catch only warned — any

  stranded a cleared, chatId-less UI until reload. It now re-adopts the
  outgoing chat on failure via `adoptChatDetail`, the restore body it newly
  shares with `loadChat`. The document's state machinery (dirty flag,
  debounced save, swap-safety flush) moved to its own `useConstitutionalDoc`
  hook when the recovery pushed `useChatSession` past its 500-line ratchet
  budget — split, not raised, per the ratchet's doctrine.
- **Route swap** (D6): `PUT /api/memories` is gone; the new route is
  `PUT /api/chats/:id/constitutional` (`{ text: string }`, 400 over
  `MAX_CONSTITUTIONAL_CHARS = 20_000` — same cap and rationale as the persona
  document). `POST /api/chats` accepts an optional `constitutional` field so a
  new chat can be created with its document already carried.
- **Carry-forward at Begin Again** (D3): `ConfirmPersonaModal` gains a
  "Constitutional memories" section — a toggle, default ON iff the outgoing
  document is non-blank, revealing an editable textarea prefilled with it.
  Toggle off (or an empty outgoing document) → no section, new chat starts
  blank. This is an explicit **copy** made at chat birth, not shared state —
  chats stay sealed units; "about me" legitimately differs between, say, a
  co-worker chat and a conversational partner.
- **No version history for the document** (D2, deliberately out of scope): the
  persona editor's forward-only audit trail exists because prompt changes
  alter Sal's behavior mid-chat; facts about the user don't need one until
  friction says otherwise.
- `Memory` leaves `lib/types.ts` — every importer (`persistence.ts`,
  `prompt.ts`, `turn-context.ts`, `useChatSession.ts`) migrates to a plain
  `constitutional: string`. The brains-isolation regression in
  `turn-context.test.ts` stays green untouched — it doesn't touch memories.

  from `configToEnv`, `redactConfig`, and `whitelistPatch` (renderer can't

## 2026-07-03 — Porter stemming in the shared tokenizer (inflection gap closed)

`tokenize()` now ends in Porter stemming, so inflection variants collide
("needles"/"needle", "painted"/"painting" → one stem) — closing the
regular-inflection half of the documented synonymy gap with pure suffix
arithmetic. No model, no data, no drift surface: the npm `stemmer` package
(pinned 2.0.1, dev-dep like chrono-node) wrapped in a new `lib/stem.ts` so the
engine's import surface stays ours. One change upgrades every consumer of the
shared tokenizer: the memory grep, the (future) brain union index, and the
spontaneity slack detector.

- **Eval ledger stays honest in both directions** — new `inflection` fixture +
  probe category: plural and verb-form pass-probes *verified to miss against
  the pre-stem tokenizer* (stash-check) and hit at rank 1 after; one new
  known-gap probe pins what Porter can't reach (irregular "ran" ↛ "running").
  Re-measured: recall@3 1.000, MRR 0.969 over 16 pass-probes (ratchets stay
  0.90). The one rank slip is documented at the measured comment.
- **A synonymy probe flipped and was repaired, not promoted**: query "approval"
  collided with planted "approved" (both → `approv`) — an inflection match
  masquerading as a synonym bridge. Query redesigned to "decision"; the
  boss-for-manager gap stays known-gap. Rule tightened in AGENTS.md:
  zero-shared-vocabulary is now measured on stems.
- **Slack detector inherits stemming intentionally** (spec D4), threshold
  untouched. Measured against the 9 real dev chats (290 windows): mean
  similarity 0.294 → 0.338, firings at 0.3 up 135 → 200. Noted in the
  spontaneity README's calibration caveat for the separate retune it already
  owns — the provisional 0.3 sits in the fat of the distribution.
- No migration: there is no stored index; scores shift deterministically at the
  next search. D2 stopword edge ("makes" → "make" survives) pinned in tests.
- Spec archived at `docs/ignored/stemming-spec.yaml`.

Small local models sometimes truncate the trailing `<turn-summary>` block at
the token cap or malform its JSON; the raw block then leaked into the visible
reply (and the grep corpus) and had to be hand-deleted. `parseTurnResponse`
(`lib/prompt.ts`) now treats any *JSON-bearing* tagged block (`{` after the
tag — the same rule `stripStreamingMeta` streams by, so prose mentions of the
tag stay visible) as a block: it is stripped from display unconditionally and
the summary is salvaged with deterministic string surgery — strict parse first,
then code-fence unwrap, `completeJson` (close open string, drop dangling comma,
close open brackets), and a cut-back-to-last-structural-boundary retry for
mid-key truncation. No model in the loop; streaming and finalized views now
agree.

- **Legacy rows self-clean at load**: the three replay paths in
  `hooks/useChatSession.ts` (hydration, chat switch, memory-editor resync) now
  share one `replayEntry` that routes persisted assistant content back through
  `parseTurnResponse`, so pre-fix rows render — and grep — clean. The DB row is
  untouched; it heals on the turn's next edit/save.
- Side fix that fell out of unifying replay: `resyncLiveChatLog` used to
  rebuild `chatLog` without summaries, silently starving the distilled summary
  buffer after a memory-editor mutation. It now rehydrates them.
- 4 pinned parser expectations deliberately updated + 8 new bork-mode tests in
  `prompt.test.ts`; verified live against the wild leaked rows (both now render
  clean, adjacent prose byte-identical).
